# 06 · Взгляд через IBM Apptio (необязательно)

<!-- plain -->
> **Обзор.** Только для компаний, которые используют ещё и IBM Cloudability или ApptioOne. Эти инструменты показывают те же начисления Azure по-своему. Страница объясняет, как сравнить их с аудитом и почему их итоги никогда не прибавляются к итогам Azure. Если IBM у вас нет, пропустите.
<!-- /plain -->

Используйте, только если **IBM Cloudability** и/или **IBM ApptioOne / TBM Studio** лицензированы и входят в охват. Оба - **представления тех же начислений Azure** (плюс, для TBM, другие финансовые источники). Никогда не складывайте их суммы с Azure Actual.

## 1. Какой продукт

| Что вы видите | Продукт | На что отвечает |
|---|---|---|
| Cost reports, Views, Business Mapping, Cost Sharing, Anomaly Detection | **Cloudability** | Затраты провайдера по сервису/аккаунту; сопоставление владельцев; распределение общих затрат |
| Data Studio, Model Studio, Report Studio, башни, приложения, BU | **ApptioOne / TBM Studio** | Распределение источник → пул → башня → приложение → BU; Cost vs Charge vs Budget |

Cloudability не обязательно питает TBM. Проследите реальную цепочку.

## 2. Когда использовать в аудите

| Шаг | Применение |
|---|---|
| 0 | Если рост впервые увидели в отчёте IBM: записать путь отчёта, метрику, версию View/модели - вопрос аудита всё равно формулируется для Azure Actual |
| 3 | Проверить, не является ли видимый в IBM рост изменением охвата/метрики/сопоставления/распределения/модели (H-IBM-*) |
| 8 | Сверить помесячные итоги Azure Actual с метрикой Cloudability, близкой к счёту, при одинаковом охвате |

## 3. Условия сопоставимости

Зафиксируйте до сравнения: vendor = Azure; биллинговый аккаунт; набор подписок; ID View (Cloudability) или версия/окружение модели (TBM); ID метрики (`unblended_cost` = Cost (Total), близка к счёту; никогда не смешивать с amortized/adjusted); валюта; календарный vs финансовый период (с утверждённым сопоставлением); время отчёта/выгрузки; проекция распределения (до/после разделения).

## 4. Проверки

### Cloudability
| ID | Проверка | Где | Сигнал проблемы |
|---|---|---|---|
| IB-C1 | Подключённые биллинговые аккаунты Azure и состав подписок во времени | Vendor credentials / accounts | Новая/пропавшая подписка на дату начала |
| IB-C2 | Определение View, используемое отчётом | Views / фильтры отчёта | Разный состав по месяцам |
| IB-C3 | ID метрики одинаков во всех месяцах | Выбор метрики отчёта / API `metrics` | Метрика сменилась |
| IB-C4 | Помесячный итог Azure vs Azure Actual (тот же охват) | Cost report по месяцу и аккаунту | Необъяснённый остаток |
| IB-C5 | Вклад сервисов / аккаунтов в Δ | Cost report по сервису, аккаунту | - |
| IB-C6 | Изменения правил Business Mapping | Organize → Business Mappings (только чтение) | Δ владельца при неизменном итоге источника |
| IB-C7 | Правила / веса Cost Sharing | Настройка Cost Sharing | Δ получателя при неизменном пуле источника |
| IB-C8 | Пересчёты при загрузке | История загрузки | Исторические месяцы изменились |
| IB-C9 | Оповещения об аномалиях | Insights → Anomaly Detection | Только контекст, не доказательство |

### ApptioOne / TBM Studio
| ID | Проверка | Где | Сигнал проблемы |
|---|---|---|---|
| IB-T1 | Путь отчёта, метрика (Cost/Charge/Budget/Forecast), объект затрат | Report Studio | Сравнивается не та метрика |
| IB-T2 | Исходная таблица и пакет затрат Azure | Data Studio | В источнике GL/ручные/не-Azure данные |
| IB-T3 | Сопоставление финансового ↔ календарного периода | Утверждённый финансовый календарь | Сдвиг периода |
| IB-T4 | Соединения/фильтры/дедупликация в трансформациях | Трансформации Data Studio | Двойной импорт, потерянные строки |
| IB-T5 | Драйверы распределения и версии | Model Studio, Check-In History | Изменение правила ≈ начало |
| IB-T6 | Нераспределённые / корзины по умолчанию | Model Studio | Δ в корзине по умолчанию |
| IB-T7 | Свежесть сборки / продвижения | Build → Calculation Queue | Устаревшая модель |
| IB-T8 | Проследить одну исходную сумму до получателей | Single Object Modeler / Trace cost flows | Остаток |

## 5. Механизмы (см. реестр гипотез H-IBM-*)

| Наблюдение | Интерпретация | Вторая проверка |
|---|---|---|
| Источник ↑, все слои ↑ | Реальный рост у провайдера | Azure Actual + драйверы Databricks (шаги 4-6) |
| Источник без изменений, получатель A ↑ / B ↓ | Смена сопоставления или распределения | История правил, равные и противоположные дельты |
| Источник без изменений, Charge в отчёте ↑ | Политика модели/начислений | Определение Charge |
| Источник ↑, получатель без изменений | Отставание модели / нераспределённое | Свежесть сборки, корзина по умолчанию |
| Отчёт ↑ только в финансовом представлении | Сдвиг периода | Календарный мост |
