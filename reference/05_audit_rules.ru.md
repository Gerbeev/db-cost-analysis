# 05 · Правила аудита R1-R12

<!-- plain -->
> **Обзор.** Двенадцать правил метода. Наиболее важные правила:
>
> - **R1** - деньгами считается только реальный счёт Azure (Actual); другие представления к нему не прибавляются.
> - **R2** - сравниваем суточные ставки спокойного периода (B) и повышенного (C).
> - **R4** - объясняем не меньше 90%; остальное показываем открыто.
> - **R6** - выгрузка должна совпадать с Cost Analysis в пределах 0,5%.
> - **R9** - причина *подтверждена* только при четырёх доказательствах.
> - **R12** - аудит только читает.
>
> Таблица ниже - точные формулировки; приложение ссылается на правила по номеру.
<!-- /plain -->

Обязательны для каждого шага. Любое отклонение обосновывается в `scope_record.md` §3.

| ID | Правило |
|---|---|
| **R1 Регистры** | **Azure Actual Cost** - денежная истина. Databricks `system.billing.usage × list_prices` - **диагностическая модель** (прайс-лист, без скидок). Azure Amortized, IBM Cloudability / ApptioOne - **альтернативные представления**. Суммы из разных регистров никогда не складываются. |
| **R2 Периоды** | Базовый **B** = ≥ 28 подряд стабильных дней до начала роста (по умолчанию 2 полных месяца). Сравнение **C** = первый полный месяц на повышенном уровне. Устойчивость **P** = месяц после C. Сравниваются **ставки в сутки** (затраты / календарные дни) и абсолютные месячные итоги. |
| **R3 Существенность** | Строка существенна, если `|Δ в сутки| ≥ 5%` от общей `|Δ в сутки|` или она входит в топ-10 положительных изменений. Исследуются все существенные строки. |
| **R4 Покрытие** | Декомпозиция останавливается, когда объяснённая положительная Δ ≥ **90%** чистой Δ. Остаток показывается как `UNEXPLAINED` и никогда не размазывается по драйверам. |
| **R5 Начало роста** | Начало = первый день `d`, когда 7-дневное скользящее среднее превышает `baseline_mean + max(2σ, 10% × baseline_mean)` и остаётся выше **≥ 14 дней подряд**. Более короткий выброс - **всплеск**. |
| **R6 Сверка** | Итог выгрузки Azure vs итог Cost Analysis при том же охвате / месяце / валюте: расхождение ≤ **0,5%** или объяснено. |
| **R7 Ценовая модель** | Модельная стоимость Databricks валидна, только если **0** записей использования имеют > 1 совпадения цены и непрайсованных записей ≤ **1%** на SKU. Иначе SKU исключается из выводов по модельной стоимости. |
| **R8 Проверка направления** | Δ% счётчика Azure *Azure Databricks* и Δ% модельной стоимости Databricks (тот же охват) имеют один знак и различаются не более чем на **15 п.п.** Иначе до анализа нагрузок разберитесь со скидками / обязательствами / охватом. |
| **R9 Доказательность** | `CONFIRMED` требует всех четырёх: (a) Δ видна в Azure Actual; (b) время изменения механизма в пределах ±2 дней от начала драйвера; (c) количественно механизм объясняет ≥ 70% Δ драйвера; (d) опровергнуто ≥ 1 альтернативное объяснение. |
| **R10 Статусы** | `CONFIRMED` · `LIKELY` (a+b или a+c) · `HYPOTHESIS` (не проверено) · `REJECTED` (опровергнуто) · `UNKNOWN` (нет данных). Один словарь везде. |
| **R11 Валюта** | Одна валюта на ряд. Никаких неявных пересчётов курса. Прайс Databricks обычно в USD; валюта счёта Azure может отличаться. |
| **R12 Только чтение** | Никаких create / modify / delete / start / stop в Azure или Databricks. Выполнение SQL расходует ресурсы warehouse - получите согласие. |

## Отметка проверок (все `CHECKS.md`; в интерфейсе - кнопки ○ ✓ - !)

| Отметка | Значение | Требование |
|---|---|---|
| `[ ]` ○ | открыто | блокирует шаг |
| `[x]` ✓ | выполнено | - |
| `[-]` - | не применимо | причина после ` | `, напр. `[-] C8.5 … | IBM not licensed` |
| `[!]` ! | выполнено с ограничением | ограничение после ` | `; записывается в scope §5 / отчёт §7 |
| Контрольная точка `G…` | выход из шага | только `[x]` |

## ID доказательств

`EVD-<шаг>-<nnn>`, напр. `EVD-04-003`. Одна строка доказательства на каждый сохранённый файл результата: файл, параметры, время запуска, наблюдение и ограничения. Интерфейс добавляет строку автоматически при каждом запуске инструмента, SQL и загрузке.
