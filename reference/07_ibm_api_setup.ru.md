# 07 · Настройка API IBM Apptio (необязательные инструменты)

<!-- plain -->
> **Обзор.** Необязательно. Как дать приложению доступ к IBM Cloudability или ApptioOne (ключи и URL), чтобы действия 8.4-8.8 могли скачать данные за вас. Если IBM не используете, пропустите.
<!-- /plain -->

> **Сначала офлайн-исследование:** полные процедуры работы с Cloudability и TBM Studio - в [reference/06 Взгляд через IBM Apptio](06_ibm_apptio_lens.md). Этот файл описывает только **необязательные API-инструменты с учётными данными**; запускать их для проекта не обязательно.

**Статус:** интеграция только для чтения собрана и проверена офлайн. Доступ к живому тенанту и финансовая сверка пока не выполнены.  
**Продукты:** IBM Cloudability (v3 cost API) и IBM ApptioOne / TBM Studio (загрузка конкретных отчётов через API).  
**Окно:** 1 января - 31 октября 2026. Все даты настраиваются.

> **Куда сохраняются результаты:** интерфейс сохраняет сырые выгрузки API в `audits/<id>/08_validation/exports/`, а анализ - в `audits/<id>/08_validation/results/`.

## 1. Определите используемый продукт

| Интерфейс / возможность | Использование | Результат API | Поддержка анализа |
|---|---|---|---|
| **IBM Cloudability** (отчёты о затратах Cloudability, Views, измерения затрат) | `cloudability` | CSV отчёта за десять месяцев и манифест доказательства | Автоматический помесячный анализ / анализ драйверов |
| **IBM ApptioOne / TBM Studio** (Cost Transparency, таблицы/отчёты) | `apptioone` | Ровно тот TSV/CSV/JSON/XLSX, что выбран в интерфейсе | Только загрузка; финансовые поля требуют проверки схемы |

У этих продуктов **разные API и учётные данные**. Наличие только ApptioOne не означает, что endpoint Cloudability лицензированы или доступны. Подтвердите право на Cloudability у администратора приложения. Не считайте отчётные суммы Cloudability дополнительными начислениями поверх счетов Azure.

## 2. Получение доступа к API только на чтение

### A. Cloudability

1. В Cloudability: **аватар пользователя → Manage Profile → Preferences → Cloudability API → Enable Access**. Скопируйте сгенерированный **API Key** в защищённое хранилище секретов. **Regenerate Key** делает предыдущий ключ недействительным; не перегенерируйте ключ уже используемой интеграции без согласования.
2. Проверьте регион развёртывания Cloudability. Выбор хоста API: `eu` (`api-eu.cloudability.com`), `us`, `apac`, `ca`, `me`, `in`, `jp`, `sg`, `usgov`.
3. Попросите администратора Cloudability о **view только для чтения**, включающем нужные подписки Azure. Запишите ID view или явно зафиксируйте, что действует view пользователя по умолчанию. **View ID `0` (поле в действии 8.5) снимает view, только если ваши права это позволяют**; это не обход привилегий.
4. Подтвердите **валюту отчётности**, показанную в интерфейсе Cloudability. Экспорт требует вручную проверенную валюту; он не выводит валюту из суммы.
5. Введите ключ в поле пароля действия 8.4 / 8.5 (используется только для этого запуска) или задайте переменную окружения `CLOUDABILITY_API_KEY` до запуска интерфейса. Никогда не вставляйте ключ в лог, тикет или скриншот.

Официальная документация IBM: [аутентификация Cloudability API v3 и региональные хосты](https://www.ibm.com/docs/en/cloudability-commercial/cloudability-enterprise/saas?topic=api-getting-started-cloudability-v3), [параметры cost reporting и пагинация](https://www.ibm.com/docs/en/cloudability-commercial/cloudability-essentials/saas?topic=api-cost-reporting-end-point).

### B. ApptioOne / TBM Studio

1. В **Enhanced Access Administration** сгенерируйте **пару API-ключей** (`keyAccess`, `keySecret`), назначьте её нужному пользователю/сервисному аккаунту и выполните **Grant Access** к целевому окружению. Нужны только права на загрузку/просмотр; не выдавайте права на выгрузку или запись для этого расследования.
2. Определите региональный хост Frontdoor (`frontdoor-eu.apptio.com` для ЕС или хост вашего тенанта) и домен клиента (например `yourdomain.com`). Скрипт получает короткоживущий `apptio-opentoken` через `POST /service/apikeylogin` и может получить ID окружения через `GET /api/environment/{customer}/{environment}`. Известный ID окружения можно указать напрямую.
3. Откройте нужный **отчёт о затратах TBM Studio**. Для таблицы: **Home → Export → Show API URL**; для таблицы/графика отчёта: контекстное меню → **Show API URL**. Скопируйте полный **HTTPS API URL** для нужных данных и периода (дата/финансовый). Не придумывайте endpoint и не меняйте ID отчёта вручную.
4. Поместите пару ключей в переменные окружения `APPTIO_KEY_ACCESS` и `APPTIO_KEY_SECRET` или введите их в поля паролей действия 8.6. **Не помещайте ключи в CMD-файлы**. Выгрузки сохраняются в приватной папке аудита (`audits/<id>/08_validation/`).
5. До любого сравнения с Azure Actual подтвердите **распределение и период (финансовый/календарный)** выгруженного отчёта, валюту, меру затрат и колонки бизнес-сопоставления. Отчёты могут быть модельными/распределёнными, а не сырыми выставленными затратами Azure.

Официальная документация IBM: [API keys/OpenToken](https://www.ibm.com/docs/en/apptio-platform/access-administration/saas?topic=apis-authentication-via-api-keys), [определение окружения](https://www.ibm.com/docs/en/apptio-platform/access-administration/saas?topic=apis-get-user-environment-information), [загрузка таблицы/отчёта TBM Studio](https://www.ibm.com/docs/en/apptio-gov/tbm-studio/saas?topic=integration-how-download-data-via-api).

## 3. Запуск инструментов из интерфейса

Откройте аудит → **шаг 08 Валидация**. Инструменты IBM - действия этого шага; результаты сохраняются в `audits/<id>/08_validation/exports/` и `…/results/` и получают строки доказательств.

| Действие | Что делает | Учётные данные |
|---|---|---|
| 8.4 Cloudability: проверка доступа | перечисляет метрики / измерения, доступные вашему пользователю (`cloudability_measures__….json`) | поле API-ключа (не сохраняется) или переменная `CLOUDABILITY_API_KEY` |
| 8.5 Cloudability: выгрузка | помесячный отчёт о затратах за окно; **валюта должна совпадать с показанной в интерфейсе Cloudability**; фильтры напр. `vendor==Azure` | то же |
| 8.6 ApptioOne: загрузка отчёта | скачивает отчёт TBM Studio по его **Show API URL** | поля key access / secret (не сохраняются) или переменные `APPTIO_KEY_ACCESS` / `APPTIO_KEY_SECRET` |
| 8.7 ApptioOne: нормализация | приводит проверенный отчёт TBM к общей схеме (выбрать колонки даты, затрат и измерений) | - |
| 8.8 Анализ выгрузки | помесячный анализ / анализ драйверов по выгрузке Cloudability или нормализованному файлу ApptioOne | - |

Ключи из формы передаются процессу инструмента как переменные окружения только на этот запуск и никогда не пишутся на диск или в логи.

Артефакты Cloudability:

- `apptio_cloudability__….csv` (`exports/` шага 08): помесячные суммы по группам (по умолчанию `metric=unblended_cost`).
- `apptio_cloudability__….manifest.json`: время извлечения, view, метрика, фильтры, количества и предупреждения о пропущенных месяцах.
- `cloudability_measures__….json`: меры, доступные пользователю, для выбора более детальных измерений.
- анализ (действие 8.8): `apptio_summary.md`, `apptio_quality.md`, `apptio_monthly.csv`, CSV точек перелома и драйверов роста в `08_validation/results/apptio_analysis__…/`.

**Детализация:** измерения по умолчанию - `vendor,enhanced_service_name`. Используйте `vendor,enhanced_service_name,resource_identifier`, только если действие 8.4 подтверждает эти измерения, а размер результата/пагинация приемлемы. Добавьте измерение подписки/аккаунта, если оно поддерживается, чтобы точно сверить охват подписок Azure. Клиент проверяет все запрошенные измерения/метрики по метаданным API тенанта. Фильтры: по одному в строке. Применение распределений меняет базу затрат и должно быть явно задокументировано. Cloudability может использовать валюту и Views организации; сравнивайте только совместимые охваты и меры.

**ApptioOne:** скопируйте реальный API URL из интерфейса TBM Studio в действие 8.6 и укажите либо домен клиента (`yourdomain.com`), либо известный ID окружения. Ничего не выгружается наружу; endpoint отчётов **только GET**. URL и его финансовый период берутся из интерфейса, а не генерируются проектом.

## 4. Проверки RCA внутри Apptio

| ID | Проверка в интерфейсе или API | Сравнение / результат |
|---|---|---|
| APP-01 | Продукт, лицензия и права на отчёты | Записать Cloudability vs ApptioOne и выбранный View/окружение |
| APP-02 | Помесячные расходы Azure за янв-окт 2026 | Сравнить `unblended_cost` Cloudability и Azure Actual при одинаковых валюте и охвате |
| APP-03 | Облачный провайдер, сервис, аккаунт/подписка, ресурс и теги | Ранжировать **дельту в валюте** апрель минус март, а не только проценты |
| APP-04 | Измерения затрат Databricks vs сопутствующих вычислений/хранилища/сети | Найти начисления, которые данные Azure относят к Databricks и managed RG |
| APP-05 | Сопоставление и правила распределения (если ApptioOne / Cost Transparency) | Различать сырые, скорректированные, амортизированные, выставленные и распределённые затраты |
| APP-06 | Аномалии Cloudability (если доступны) и пропуски загрузки затрат | Определить, когда начались всплески и не было ли задержки загрузки |
| APP-07 | Views, фильтры исключения, кредиты, курс и изменения бизнес-сопоставления | Объяснить расхождения и кажущийся рост из-за конфигурации |
| APP-08 | Группы нагрузок с наибольшим ростом | Сопоставить сервис/ресурс Apptio со счётчиками Azure и SKU/задачами Databricks |

Необязательный endpoint аномалий Cloudability (зависит от продукта/прав): [`GET /v3/anomalies`](https://www.ibm.com/docs/en/cloudability-commercial/cloudability-enterprise/saas?topic=api-anomaly-detection-endpoint). Его параметры и `viewId` нужно проверить на тенанте, прежде чем опираться на результат; данные аномалий не являются финансовым регистром.

## 5. Сверка охвата - обязательно

- **Azure Actual**: база выставленного регистра для объявленного биллингового охвата Azure Cost Management.
- **Databricks `system.billing`**: потребление / оценочная атрибуция продуктов (может быть по прайсу, скидки отличаются).
- **Cloudability**: независимая FinOps-агрегация загруженных облачных затрат; может уже включать те же начисления Azure и использовать другие корректировки, распределения, задержки или фильтры.
- **ApptioOne / TBM Studio**: модельные/распределённые итоги TBM могут строиться на тех же загруженных данных Azure; смотрите определения таблиц и колонок, а не только показанное число.

**Никогда не суммируйте эти четыре представления.** Для корректного сравнения выровняйте период, валюту счёта, охват подписок, провайдера, view, распределения, меру затрат (Actual vs amortized), кредиты и время обновления выгрузки. Любые различия записывайте как неразрешённые, пока они не объяснены доказательствами.

## 6. Обработка сбоев и безопасность

| Симптом | Действие |
|---|---|
| HTTP 401 / 403 | Проверить ключ, регион, права и выбранный view/окружение |
| HTTP 404 | Проверить путь endpoint или скопированный API URL TBM Studio |
| HTTP 429 / 5xx | GET только для чтения использует ограниченные повторы, `Retry-After` и ограниченную задержку; при необходимости повторите с более узким запросом |
| Отсутствующие/неизвестные меры | Выполнить действие 8.4, затем выбирать только имена, возвращённые тенантом |
| Пропущенный месяц / смешанная валюта | Не считать пропуски нулём, не сравнивать endpoint при смене валюты |
| В результате ноль строк | Проверить фильтр Azure, выбранный view, задержку загрузки, покрытие данных и даты биллинга |
| Ротация API-ключа | Обновить секрет вне проекта; никогда не сохранять учётные данные в архиве |

Запросы выгрузки проверяют TLS, блокируют HTTP-редиректы (чтобы не утёк токен), ограничивают размер ответа и пагинацию, пишут CSV атомарно и никогда не логируют значения учётных данных. Скрипты не вызывают API записи/изменения/удаления. `audits/_logs/apptio_api.log` сбрасывается при каждом вызове API; офлайн-анализатор пишет в `audits/_logs/analysis.log`.

## 7. Критерии приёмки

- [ ] Продукт и регион подтверждены, API-ключ включён с доступом только на чтение.
- [ ] Проверка доступа к API проходит, измерения/метрики задокументированы.
- [ ] Выгружены десять полных месяцев с манифестом, полными счётчиками строк/страниц и определённым view.
- [ ] Валюта и метрика затрат Cloudability сверены с интерфейсом.
- [ ] Предупреждения о пропущенных месяцах, пагинации и качестве данных устранены.
- [ ] Помесячные итоги сверены с соответствующим охватом Azure Actual или исключения перечислены.
- [ ] Основные приросты связаны с сервисами/счётчиками Azure и задачами/SKU Databricks с подтверждающими доказательствами.
- [ ] Реестр доказательств и выводы RCA обновлены; никаких оптимизаций в проде без согласования.

## 8. Нормализация CSV/TSV ApptioOne для локального анализа

**Только после проверки фактической схемы отчёта и смысла затрат.** Экспорт TBM Studio сохраняет исходные колонки отчёта; он не может надёжно вывести календарные месяцы, валюту, финансовое сопоставление или смысл каждого поля затрат.

1. В TBM Studio выберите **помесячную** таблицу затрат только для чтения с колонками календарного месяца, числовых затрат и хотя бы одного значимого бизнес-измерения (центр затрат, приложение или сервис). Предпочтительно TSV через **Show API URL**.
2. Подтвердите, использует ли отчёт календарные даты или финансовый календарь. `normalize_apptioone.py` принимает только `YYYY-MM` и `YYYY-MM-DD`. Для финансовых периодов получите проверенное календарное сопоставление до нормализации; скрипт никогда не угадывает финансовый месяц.
3. В действии 8.7 выберите **точные колонки** выгруженного отчёта (месяц, затраты, одно или несколько измерений), валюту, имя метрики затрат из интерфейса TBM и метку отчёта. Затем проанализируйте нормализованный файл действием 8.8, отдельно от Cloudability.

Результат содержит манифест доказательства и предупреждения о пропущенных месяцах. Никогда не объединяйте и не складывайте итоги этого отчёта с Azure Actual или Cloudability.
