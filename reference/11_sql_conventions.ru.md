## Параметры

Именованные маркеры параметров; SQL Editor показывает виджет для каждого маркера. Даты - текстом `YYYY-MM-DD`. **Все значения `_end` не включаются** (первый день после периода).

| Параметр | Значение | Пример |
|---|---|---|
| `:start_date` / `:end_date` | Окно анализа | `2026-01-01` / `2026-11-01` |
| `:base_start` / `:base_end` | Базовый период B | `2026-01-01` / `2026-03-01` |
| `:cmp_start` / `:cmp_end` | Период сравнения C | `2026-04-01` / `2026-05-01` |
| `:object_ids` | Список ID объектов из 5.3 через запятую или `ALL` | `123456789,0412-abc123-xyz` |
| `:cluster_sources` | `ALL` или список через запятую (`UI,API` / `JOB`) | `UI,API` |
| `:required_tag` | Ключ тега, который должен быть | `cost_center` |

Запросы к биллингу фильтруют `cloud = 'AZURE'`.

## Соединение с прайсом (в каждом запросе стоимости)

```sql
LEFT JOIN system.billing.list_prices p
  ON  p.account_id = u.account_id AND p.cloud = u.cloud
  AND p.sku_name = u.sku_name     AND p.usage_unit = u.usage_unit
  AND u.usage_start_time >= p.price_start_time
  AND (p.price_end_time IS NULL OR u.usage_start_time < p.price_end_time)
```
Сначала проверьте `1.3_price_join_check.sql` (R7). Модельная стоимость = `usage_quantity × pricing.effective_list.default` (прайс-лист, не счёт).

## Сохранение результатов

В интерфейсе каждое SQL-действие подставляет эти параметры из аудита, может выполнить запрос напрямую (Настройки → подключение Databricks SQL; Statement Execution API только для чтения) и сохраняет CSV под правильным именем вместе со строкой доказательства. Без подключения: скопируйте запрос, выполните его в SQL-редакторе и загрузите CSV в том же действии.

- Выгружайте полный результат (без лимита строк интерфейса) в CSV в `audits/<id>/<step>/results/`.
- Имя файла: `<sql-id>__<детали>__<YYYYMMDD>.csv`, напр. `5.3_object_delta__B2026-02_C2026-04__20261109.csv`.
- Строка доказательства: файл, параметры, время запуска, наблюдение.

## Соглашения внутри SQL

- Корректировки: все значения `record_type` сохраняются и взаимозачитываются.
- Единицы: количества суммируются только в пределах одного `usage_unit`.
- Региональные таблицы (`lakeflow`, `compute`, `query`, `access`): выполнять в каждом регионе с workspace из охвата.
- Если колонка не найдена (эволюция схемы, preview-функции), уберите её и отметьте это в строке доказательства.
