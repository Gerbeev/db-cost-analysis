# Инструменты

Python 3.10+, только стандартная библиотека. По отношению к источникам данных - только чтение. **Их запускает веб-интерфейс** (`run.cmd` → действия шагов); эта страница описывает, что делает каждый.

| Инструмент | Действия в интерфейсе | Назначение |
|---|---|---|
| `new_audit.py` | Аудиты → Новый аудит | Создать `audits/<id>/` из `playbook/*/CHECKS.md` и `templates/` |
| `check_audit.py` | при каждом изменении (статус шага, `STATUS.md`) | Оценить проверки, обязательные результаты и проверки данных по шагам |
| `period_delta.py` | 1.4, 2.1 (помесячный ряд); 3.5, 3.6 (Δ/сутки по группировке), 4.1 (пять группировок); расчёты 2.7, 3.9 | Ранжировать Δ/сутки между B и C по любым колонкам; помесячный ряд; существенность R3, покрытие R4 |
| `onset_detect.py` | 2.3 | Определение начала роста / всплеска по правилу R5 в суточном ряду (строки суммируются по дням) |
| `analyze_costs.py` | 2.9 | Помесячные отчёты из CSV Azure Actual + выгрузки SQL 2.2 (раздельные регистры) |
| `azure_workspace_inventory.ps1` | 4.2 (Python-порт в `webapp/runner.py`, те же колонки) | Инвентаризация workspace ↔ managed RG через Azure CLI (только чтение) |
| `apptio_api.py`, `normalize_apptioone.py`, `analyze_apptio.py` | 8.4-8.8 | Необязательная выгрузка и анализ IBM Cloudability / ApptioOne ([reference/07](../reference/07_ibm_api_setup.md)) |
| `tests/` | Настройки → Самопроверка | Модульные тесты на синтетических данных (инструменты и интерфейс) |

`period_delta` и `onset_detect` сами находят типичные колонки Azure (`Date`/`UsageDate`, `CostInBillingCurrency`/`Cost`, `BillingCurrencyCode`/`BillingCurrency`/`Currency`), принимают `YYYY-MM-DD` и `MM/DD/YYYY` и отказываются работать со смешанными валютами (используйте поле *валюта* действия). Конец периода не включается.

Каждый запуск из интерфейса записывает свои параметры в `evidence_register.csv` (колонка `parameters`, JSON) - именно их перезапускает расчёт воспроизведения (8.1).

Логи инструментов IBM: `audits/_logs/`.
