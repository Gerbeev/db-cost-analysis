# Шаг 09 - Отчёт и контроль

[08 Валидация](../08_validation/README.md) ← `09` · [Оглавление плейбука](../README.md)

<!-- plain -->
> **Обзор.** Завершающий шаг превращает анализ в результат, пригодный для действий: отчёт с мостом дельты, по одному выводу на причину, список исправлений с владельцами и оповещения, которые выявляют следующий рост за дни, а не за месяцы.
>
> Экономия существует, только когда она видна в реальном счёте. До этого момента это план.
>
> **Результат:** `findings_report.md` с таблицей моста, списком исправлений и планом контроля.
>
> **Важно:** Таблица моста в отчёте должна совпадать с delta_bridge.csv.
<!-- /plain -->

**Цель:** утверждённый отчёт о выводах, план исправлений и план контроля.
**Входные данные:** G8 пройдена. **Где работать:** `audits/<id>/09_report_and_controls/findings_report.md`.

## Что сделать

| # | Действие | Где |
|---|---|---|
| 9.1 | Резюме: одно предложение на каждый подтверждённый драйвер с суммой в валюте/сутки и долей | отчёт §1 |
| 9.2 | Таблица размера/времени, графики (помесячный ряд в сутки; суточный ряд с порогом R5) | отчёт §2 |
| 9.3 | Мост дельты из `delta_bridge.csv` (действие 9.1 выводит его таблицей markdown) | отчёт §3 |
| 9.4 | Блок вывода на каждый драйвер (из карточек) | отчёт §4 |
| 9.5 | Отклонённые гипотезы, остаток, ограничения | отчёт §5-§7 |
| 9.6 | Исправление по каждому драйверу: изменение, **диапазон** экономии, риск, контрольная метрика, откат, владелец, проверка ([reference/08](../../reference/08_remediation_and_controls.md)) | отчёт §8 |
| 9.7 | План контроля: бюджеты / оповещения, политики вычислений, еженедельный обзор крупнейших изменений, целевое покрытие тегами | отчёт §8 |
| 9.8 | Утверждение владельцем аудита; владельцы исправлений названы | отчёт §9 |

Экономия заявляется только после замера в Azure Actual после изменения (≥ 14 дней, тот же метод).
