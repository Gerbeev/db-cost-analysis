# Плейбук - аудит роста затрат Azure Databricks

<!-- plain -->
> **Обзор.** Плейбук - это десять шагов по порядку. Каждый шаг отвечает на один вопрос и заканчивается **контрольной точкой** - проверкой, которую нужно отметить перед следующим шагом. Вводить команды не нужно: каждое действие - кнопка на странице шага в приложении, а каждый результат сохраняется в папке вашего аудита.
>
> Последовательность: *договоритесь о вопросе (00) → поверьте данным (01) → докажите рост (02) → уберите учётные эффекты (03) → найдите, куда ушли деньги в Azure (04) и в Databricks (05) → найдите причину (06) → проверьте, что числа сходятся (07) → дайте их повторить другому (08) → оформите результат (09).*
<!-- /plain -->

Базовые знания: [reference/00_fundamentals.md](../reference/00_fundamentals.md).

Десять шагов, выполняются по порядку. В интерфейсе каждый шаг - страница с действиями (кнопками), проверками, обязательными результатами и автоматическими проверками данных. В папке каждого шага:

- `README.md` - что делать, какой инструмент / SQL, **куда сохраняется каждый результат** в папке аудита. В интерфейсе каждая строка - действие на странице шага.
- `CHECKS.md` - список проверок шага (копируется в аудит при создании). Шаг закрыт, когда каждая строка решена, обязательные результаты есть и автоматические проверки пройдены - страница шага показывает все три условия в реальном времени.
- `sql/` - SQL только для чтения для шага (где нужен).

| Шаг | На какой вопрос отвечает | Контрольная точка |
|---|---|---|
| [00 Постановка](00_frame/README.md) | Что именно проверяем - охват, периоды, валюта, регистр? | G0 охват утверждён |
| [01 Качество данных](01_data_quality/README.md) | Данные полные, без дублей, в одной валюте, оцениваемые? | G1 R6 + R7 пройдены |
| [02 Подтверждение и размер](02_confirm_and_size/README.md) | Выросли ли выставленные затраты, на сколько в сутки, с какого дня? | G2 Δ/сутки > 0, начало датировано |
| [03 Учётные эффекты](03_accounting_effects/README.md) | Сколько дают календарь / покупки / кредиты / курс / охват / цена? | G3 операционная Δ рассчитана |
| [04 Декомпозиция Azure](04_azure_decomposition/README.md) | По каким сервисам / счётчикам / ресурсам выставлено больше? | G4 корзины сходятся |
| [05 Декомпозиция Databricks](05_databricks_decomposition/README.md) | Какие продукты / SKU / workspace / объекты потребили больше? | G5 ≥ 90 % покрыто |
| [06 Первопричина](06_root_cause/README.md) | Что изменилось, когда и сколько это объясняет? | G6 ни одного драйвера в статусе гипотезы |
| [07 Атрибуция и остаток](07_attribution_and_residual/README.md) | Кому принадлежит каждая часть; что не объяснено? | G7 мост сходится, остаток ≤ 10 % |
| [08 Валидация](08_validation/README.md) | Цифры воспроизводимы, утверждения доказаны? | G8 подпись проверяющего |
| [09 Отчёт и контроль](09_report_and_controls/README.md) | Что докладываем, исправляем и отслеживаем? | G9 отчёт утверждён |

```
00 Постановка → 01 Качество → 02 Подтверждение → 03 Учётные эффекты → 04 Декомпозиция Azure
                                                                              │
09 Отчёт ← 08 Валидация ← 07 Атрибуция и остаток ← 06 Первопричина ← 05 Декомпозиция Databricks
```

## Быстрый путь (первые 2 часа)

Чтобы быстро найти доминирующий драйвер, выполните только: 02 (2.1, 2.3, 2.7) → 03 (3.2, 3.3) → 04 (4.1) → 01 (1.8 соединение с прайсом) → 05 (5.1, 5.3) → 06 (один плейбук). Всё найденное так - `LIKELY`, пока не пройдены шаги 07-08.
