> **Обзор.** Общий рост - одно число. Этот шаг раскладывает его по подпискам, сервисам, счётчикам, группам ресурсов и ресурсам. Каждое разложение - альтернативное представление одного и того же итога: рассматривайте их по одному и не суммируйте два представления.
>
> Результат - ранжированный список крупнейших увеличений, каждое отнесено к категории затрат: счёт Databricks, лежащие под ним виртуальные машины, хранилище, сеть, мониторинг либо позиции вне аудита.
>
> **Результат:** строки BUCKET в мосте дельты и карта workspace → группы ресурсов.
>
> **Важно:** Сохраняйте и убывающие строки. Их исключение завышает остальные увеличения.
<!-- /plain -->

**Цель:** понять, *что выставлено больше*, построчно, по одной взаимоисключающей группировке за раз, и отнести каждую существенную строку к корзине затрат.
**Входные данные:** G3 пройдена; выгрузка Azure из шага 01. **Где работать:** `audits/<id>/04_azure_decomposition/`.
**Формулы и существенность (R3):** [reference/03 §3](../../reference/03_analysis_method.md).

## Что сделать

Каждая группировка - действие в интерфейсе, выгрузка, B и C уже подставлены из аудита; результат сохраняется в `audits/<id>/04_azure_decomposition/results/` вместе со строкой доказательства.

| # | Группировка | Действие | Сохраняется как |
|---|---|---|---|
| 4.1 | Подписка, сервис, счётчик, группа ресурсов, ресурс (топ 50) | Действие 4.1 в интерфейсе - один запуск записывает все пять группировок (`SubscriptionId`; `ServiceName`; `ServiceName,MeterCategory,MeterName`; `SubscriptionId,ResourceGroup`; `ResourceId`) | `results/delta_by_subscription__….csv`, `delta_by_service`, `delta_by_meter`, `delta_by_resource_group`, `delta_by_resource` |
| 4.2 | Карта workspace ↔ managed RG ↔ зависимые RG | Действие 4.2 в интерфейсе - инвентаризация через Azure CLI, только чтение (нужен `az login`), либо собрать в Портале → Azure Databricks → workspace → Overview и загрузить (4.2b) | `results/workspace_rg_map__….csv` |

Имена колонок зависят от схемы выгрузки (EA / MCA различаются) - если колонки нет, действие покажет доступные колонки.

Затем отнесите каждую **существенную** строку (R3: `|Δ/сутки| ≥ 5%` итога или топ-10 положительных) к одной корзине и добавьте по строке на корзину в `delta_bridge.csv` с `category = BUCKET` (справочный подытог, не входит в тождество моста; на шаге 06 заменяется строками `ROOT_CAUSE`):

| Корзина | Типичные строки Azure | Продолжение |
|---|---|---|
| `DBX_PLATFORM` | Сервис *Azure Databricks* (DBU, счётчики serverless) | Шаг 05 |
| `DBX_CLASSIC_INFRA` | Virtual Machines, Managed Disks, Public IP, Load Balancer в **managed RG** workspace | Шаг 05 + плейбуки 03 / 04 |
| `STORAGE` | Объём / транзакции / репликация хранилища lake, DBFS, UC | Плейбук 09 |
| `NETWORK` | Трафик, NAT Gateway, Private Link, Firewall, VPN / ExpressRoute | Плейбук 10 |
| `MONITORING` | Log Analytics, Azure Monitor | Плейбук 11 |
| `SHARED_UNALLOCATED` | Общие ресурсы без доказанного ключа распределения | Шаг 07 |
| `OUT_OF_SCOPE` | Сервисы, не связанные с Databricks | Строка моста `OOS-01` |

Отрицательные изменения сохраняйте. Managed RG - подсказка для сопоставления, а не доказательство владения.

## Автоматические проверки

- Все `results/delta_by_*.csv` должны давать **одинаковую** дельту в сутки (один регистр, разные группировки) - расхождение означает разные фильтры или периоды.
