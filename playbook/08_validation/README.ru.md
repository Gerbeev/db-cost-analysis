# Шаг 08 - Валидация выводов

<!-- plain -->
> **Обзор.** Перед отчётом результаты проверяются. Приложение заново запускает каждый сохранённый инструмент и SQL-запрос с записанными параметрами и проверяет, что результаты идентичны. Затем проверяющий, не выполнявший анализ, изучает его и оспаривает выводы.
>
> При наличии IBM Cloudability или ApptioOne цифры можно сопоставить с их данными. Расхождения объясняются, но не суммируются.
>
> **Результат:** журнал воспроизведения, пониженные статусы там, где доказательств мало, и подпись проверяющего.
>
> **Важно:** Строки, созданные вручную, приложение повторить не может: проверьте их вручную.
<!-- /plain -->

**Цель:** выводы выдерживают независимую проверку; каждое число в отчёте воспроизводимо.
**Входные данные:** G7 пройдена. **Где работать:** `audits/<id>/08_validation/`.

## Что сделать

| # | Действие | Куда сохранить (`audits/<id>/08_validation/…`) |
|---|---|---|
| 8.1 | Перезапустить каждый запрос / инструмент из `evidence_register.csv` с теми же параметрами и сравнить значения - расчёт 8.1 перезапускает инструменты (и SQL при наличии подключения) автоматически; строки `MANUAL` разбираются вручную | `results/reproduction_log__….md` (evidence_id, значение повтора, совпадение Y/N) |
| 8.2 | Перепроверить R9 для каждого `CONFIRMED`; понизить до `LIKELY`, если не хватает критерия | `hypothesis_register.csv` |
| 8.3 | Сверить альтернативные представления: Azure Amortized (шаг 03), дашборд использования Databricks; **IBM** при наличии лицензии ([reference/06](../../reference/06_ibm_apptio_lens.md)) - расхождения объясняются, но не суммируются | `results/cross_check.md`; `ibm_discrepancy_register.csv` |
| 8.4 | Устойчивость: сохраняется ли каждый драйвер в P? Вернулся → всплеск / разовое событие | карточки драйверов, `notes.md` |
| 8.5 | Независимая проверка (человеком, не строившим анализ) | `scope_record.md` §8 |

## Автоматические проверки

- В `evidence_register.csv` есть строки доказательств.
- Каждая гипотеза `CONFIRMED` ссылается на ID доказательств, существующие в реестре.

## Контрольная точка G8

Все числа воспроизводимы; подпись проверяющего в §8.
