# Шаг 01 - Фиксация данных и проверка качества

[00 Постановка](../00_frame/README.md) ← `01` → [02 Подтверждение и размер](../02_confirm_and_size/README.md) · [Оглавление плейбука](../README.md)

<!-- plain -->
> **Обзор.** На этом шаге данные загружаются и проверяются на целостность. Большинство неверных выводов в аудитах затрат возникает из-за входных данных, а не анализа: месяц выгружен дважды, в одной колонке две валюты, за день нет записей.
>
> Вы скачиваете из портала Azure одну детальную выгрузку и один сводный отчёт для сверки, затем выполняете SQL-проверки в Databricks (только чтение). Приложение рассчитывает сверку и сообщает, пройдена ли она.
>
> **Результат:** основной файл выгрузки в аудите, зелёная сверка R6 и список SKU, исключённых из модели.
>
> **Важно:** Выгружайте один запуск на месяц. Не объединяйте запуски: перекрывающиеся запуски удваивают затраты.
<!-- /plain -->

**Цель:** один полный, дедуплицированный, сопоставимый набор данных на каждый регистр до расчёта любых дельт.
**Входные данные:** утверждённый охват (G0). **Где работать:** `audits/<id>/01_data_quality/`.
**Как работать с порталами и выгрузками:** [reference/02](../../reference/02_access_and_data_collection.md).

## Что сделать

| 1.4 | Помесячные итоги выгрузки | действие 1.4 (инструмент *Помесячный ряд*) | `results/export_monthly__….csv` |
| 1.5 | Сравнить 1.3 и 1.4 по месяцам (R6 ≤ 0,5%) | действие 1.5 (расчёт *Сверка R6*) | `results/R6_reconciliation.csv` (month, export, cost_analysis, diff %) |

SQL-действия (1.6-1.8) показывают запрос с параметрами, уже подставленными из периодов аудита: выполните его прямо из интерфейса, если настроено подключение к Databricks (**Настройки**), или скопируйте в SQL-редактор Databricks и загрузите CSV в том же действии. Соглашения: [reference/11](../../reference/11_sql_conventions.md).

## Автоматические проверки (на странице шага)

- Выгрузка: одна валюта (STOP-2), нет пропущенных месяцев (STOP-3), число точных дублей строк (подсказка STOP-1).
- `1.3_price_join_check`: список SKU с вердиктом `FAIL_*` - их нужно исключить из модельной стоимости.

## Стоп-правила

Перекрывающиеся запуски выгрузки, смешанные валюты, пропущенные месяцы → **не считайте дельты**, пока это не исправлено ([reference/04](../../reference/04_pitfalls_and_stop_rules.md)).

## Контрольная точка G1

R6 и R7 пройдены, либо проблемный охват / SKU исключены и записаны как ограничения в §5.
