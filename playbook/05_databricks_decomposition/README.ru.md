# Шаг 05 - Декомпозиция потребления Databricks

[04 Декомпозиция Azure](../04_azure_decomposition/README.md) ← `05` → [06 Первопричина](../06_root_cause/README.md) · [Оглавление плейбука](../README.md)

<!-- plain -->
> **Обзор.** Шаг 04 установил, насколько выросли затраты Databricks. Этот шаг определяет, какие объекты за это отвечают, от общего к частному: продукт, workspace, затем отдельная задача, конвейер, SQL warehouse или кластер. Все запросы - SQL только на чтение к системным таблицам Databricks.
>
> Хороший результат - короткий список, обычно от трёх до десяти объектов, которые вместе объясняют 90% роста. Эти объекты - кандидаты в драйверы.
>
> **Результат:** строки DRIVER_CANDIDATE в мосте дельты и открытые гипотезы для каждой.
>
> **Важно:** Денежные оценки считайте только по SKU, прошедшим проверку R7 на шаге 01. Не складывайте количества в разных единицах.
<!-- /plain -->

**Цель:** объяснить `DBX_PLATFORM` (и через это `DBX_CLASSIC_INFRA`) по цепочке продукт → SKU → workspace → объект и составить список кандидатов в драйверы.
**Входные данные:** G4 пройдена; B / C из scope §3; SKU, не прошедшие R7 (шаг 01), исключены из денежных выводов.
**Где работать:** `audits/<id>/05_databricks_decomposition/results/`. Параметры SQL `:base_start`, `:base_end`, `:cmp_start`, `:cmp_end` подставляются из аудита; `:object_ids` для 5.4 заполняется основными объектами из последнего результата 5.3. Выполняйте в интерфейсе (подключение Databricks) или копируйте + загружайте ([reference/11](../../reference/11_sql_conventions.md)).

## Правила

- Количества - только в пределах одного `usage_unit`; деньги - только для SKU, прошедших R7.
- Классические вычисления: DBU (здесь) и VM (шаг 04) выставляются **оба** - это не дубли.
- Serverless: вычисления входят в цену DBU; стоимость VM никогда не добавляется.
- `job_id` пуст для задач на all-purpose кластерах - такое потребление видно как `CLUSTER`.

## Автоматические проверки

- `5.3_object_delta`: сколько объектов набирают 90% модельной дельты (R4).

## Контрольная точка G5

Основные объекты объясняют ≥ 90% модельной Δ `DBX_PLATFORM`, либо неатрибутированный остаток количественно оценён.
