# Шаг 00 - Постановка вопроса

<!-- plain -->
> **Обзор.** Аудит начинается с наблюдения: счёт за Azure Databricks вырос. Этот шаг превращает наблюдение в точный вопрос, который можно утвердить: какой счёт, какие подписки, какие месяцы, какая валюта.
>
> Шаг носит документарный характер, но предотвращает самую дорогую ошибку аудита. Изменение охвата после сбора данных обесценивает все уже собранные числа.
>
> **Результат:** заполненный `scope_record.md` (разделы 1-4 и 8) и периоды, сохранённые в приложении.
>
> **Важно:** Используйте только полные месяцы. Текущий месяц не завершён и должен остаться вне окна.
<!-- /plain -->

`00` → [01 Качество данных](../01_data_quality/README.md) · [Оглавление плейбука](../README.md)

**Цель:** записанный однозначный вопрос аудита, охват и набор периодов, утверждённые до начала работы с данными.
**Перед началом:** [reference/00 Основы](../../reference/00_fundamentals.md) (слои затрат, DBU, обязательства).
**Входные данные:** отчёт или оповещение, ставшее поводом для аудита; доступ к владельцу аудита.
**Где работать:** `audits/<id>/scope_record.md` (§1-§4), `audits/<id>/00_frame/notes.md`.

## Что сделать

| # | Действие | Где записать |
|---|---|---|
| 0.1 | Создать аудит в интерфейсе (**Аудиты → Новый аудит**, напр. `2026-04-dbx-growth`); задать окно, предварительные B / C / P и валюту (действие 0.1) | `audits/<id>/`, `audit.json`, §3 |
| 0.2 | Записать повод: кто увидел рост, в каком отчёте, какая метрика (счёт, Cost Analysis, дашборд использования Databricks, отчёт IBM) | `scope_record.md` §1 |
| 0.3 | Сформулировать вопрос аудита в денежном регистре: *«Azure Actual Cost для охвата S вырос с X/сутки (B) до Y/сутки (C). Какие механизмы объясняют ≥ 90%?»* | §1 |
| 0.4 | Зафиксировать охват: биллинговый аккаунт/профиль, подписки, аккаунт Databricks + ID workspace + регионы, managed RG каждого workspace, зависимые RG (хранилище lake, VNet/NAT/Private Link, Log Analytics) | §2 |
| 0.5 | Зафиксировать окно: только полные месяцы (обычно 10-12), текущий неполный месяц исключён; предварительные B / C / P | §3 |
| 0.6 | Зафиксировать валюту, тип договора (EA / MCA / MPA), контракты с датами (DBCU, резервирования, savings plans, кредиты) | §2, §3 |
| 0.7 | Перечислить все источники данных и статус доступа (OK / DENIED / UNKNOWN) - см. [таблицу доступов](../../reference/02_access_and_data_collection.md#1-minimum-read-access) | §4 |
| 0.8 | Записать отклонения от правил аудита R1-R12 ([правила](../../reference/05_audit_rules.md)) или «none» | §3 |
| 0.9 | Получить утверждение владельца аудита; записать имя и дату | §8 |

## Проверки

Отмечайте в интерфейсе (шаг 00 → **Проверки**); статус обновляется автоматически. Полный список: [CHECKS.md](CHECKS.md).

## Контрольная точка G0

Охват, периоды, валюта и регистр записаны и утверждены. **Не запрашивайте выгрузки до G0** - неверный охват обесценивает всю дальнейшую работу.
