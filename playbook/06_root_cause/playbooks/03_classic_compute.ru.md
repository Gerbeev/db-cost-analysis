# PB-CLASSIC - классические вычисления

<!-- plain -->
> **Обзор.** Используйте, когда стали дороже кластеры в вашей подписке Azure, особенно **all-purpose** кластеры, которыми пользуются люди. Типичные причины: кластеры остаются включёнными, более крупные узлы, больше узлов, нет автоостановки, задачи идут на интерактивных кластерах.
<!-- /plain -->

**Сигналы:** DBU `ALL_PURPOSE`/`INTERACTIVE`/классических `JOBS`/`SQL` ↑ **и** счётчики VM ↑ в managed RG; `5.3` объекты `CLUSTER` ↑.

**Диагностика**

| # | Проверка | Источник | Что смотреть |
|---|---|---|---|
| C1 | История конфигурации кластеров с базой до окна | [`6.06_cluster_config_history.sql`](../sql/6.06_cluster_config_history.sql) | `auto_termination_minutes`, воркеры, min/max автомасштабирования, типы узлов, availability |
| C2 | Узло-минуты, загрузка CPU/памяти | [`6.07_node_utilization.sql`](../sql/6.07_node_utilization.sql) | Узло-минуты ↑; доля минут с низким CPU |
| C3 | Стоимость кластеров B vs C | [`5.3_object_delta.sql`](../../05_databricks_decomposition/sql/5.3_object_delta.sql) (object_type `CLUSTER`) | Основные кластеры |
| C4 | Счётчики VM по размеру VM и модели цены | Cost Analysis: Meter + *Pricing model* + Resource (managed RG) | Смена семейства VM; Spot vs On-demand |
| C5 | Диски | Cost Analysis: счётчики Managed Disks в managed RG | Рост Premium/размера |
| C6 | Кто создавал/изменял кластеры | [`6.14_audit_change_events.sql`](../sql/6.14_audit_change_events.sql) (сервис `clusters`) | Исполнитель и время |
| C7 | Наблюдаемые DBU на узло-час (тип узла, SKU, Photon) | [`6.15_dbu_per_node_hour.sql`](../sql/6.15_dbu_per_node_hour.sql) (запустить для B и C) | `dbu_per_node_hour` ↑ при том же типе узла = Photon/SKU/уровень (H-CLS-07); смена состава типов узлов = H-CLS-03 |

**Механизмы**

| ID | Механизм | Подтверждает | Опровергает |
|---|---|---|---|
| H-CLS-01 | Автоотключение выключено или увеличено | `auto_termination_minutes` 0 или ↑ на дату начала; узло-минуты ↑ при низком CPU | Не менялось; загрузка пропорциональна |
| H-CLS-02 | Больше воркеров / выше минимум автомасштабирования | Изменение воркеров/минимума на дату начала; узло-минуты ↑ | Конфигурация не менялась |
| H-CLS-03 | Большее / более дорогое семейство VM | Смена типа узла; счётчик VM переходит на новый размер | Те же типы узлов |
| H-CLS-04 | Больше интерактивных кластеров / пользователей | Новые объекты `CLUSTER` (`cluster_source = UI/API`) | Тот же набор кластеров |
| H-CLS-05 | Избыточный размер (низкая загрузка) | `sampled_low_cpu_minutes / observed_node_minutes` ≥ 50% в C и ↑ vs B | Высокая загрузка |
| H-CLS-06 | Откат со Spot на on-demand | Изменение `azure_availability` или переход Pricing model VM на On-demand; стоимость VM ↑ ≫ DBU ↑ | Availability не менялась |
| H-CLS-07 | Photon / runtime / уровень повышают ставку DBU | `dbu_per_node_hour` или доля SKU/Photon ↑ при тех же типах узлов (`6.15`) | Тот же SKU и коэффициент не изменился |
| H-CLS-08 | Рост дисков | Счётчики Managed Disk ↑; включён elastic disk | Счётчики дисков не изменились |

**Варианты исправления:** политики кластеров (максимум автоотключения, максимум воркеров, разрешённые типы узлов); job-кластеры для плановых задач; shared-кластеры для интерактивных пользователей; spot с откатом, где это допустимо; подбор размера после анализа загрузки.
