# PB-STORAGE - хранилище

<!-- plain -->
> **Обзор.** Используйте, когда выросла категория **STORAGE**: хранится больше данных, дольше срок хранения, много мелких файлов или больше чтений и записей.
<!-- /plain -->

**Сигналы:** счётчики Azure Storage ↑ на аккаунтах хранения lake / workspace / UC.

| # | Проверка | Источник | Что смотреть |
|---|---|---|---|
| T1 | Разделить объём vs транзакции vs репликация vs egress | Cost Analysis: Storage, группировка по Meter subcategory/Meter, по аккаунту хранения | Какой тип счётчика |
| T2 | Динамика объёма | Аккаунт хранения → Insights / Metrics (`UsedCapacity`) | ТБ ↑ |
| T3 | Динамика транзакций | Metrics (`Transactions` по API name) | List/read/write ↑ |
| T4 | Политики | Lifecycle management, soft delete, versioning, избыточность (Activity Log) | Изменение ≈ начало |
| T5 | Сторона Databricks | Расписания обслуживания таблиц (OPTIMIZE/VACUUM); новые задачи, читающие те же пути (`5.3`) | Нагрузка за транзакциями |

| ID | Механизм | Подтверждает | Опровергает |
|---|---|---|---|
| H-STO-01 | Рост объёма (хранение, нет VACUUM, новые наборы данных) | Счётчик объёма ↑, `UsedCapacity` ↑ | Объём не изменился |
| H-STO-02 | Всплеск транзакций (мелкие файлы, листинг, повторы, новые читатели) | Счётчики транзакций ↑ при неизменном объёме; совпадает начало задачи | Транзакции не изменились |
| H-STO-03 | Смена уровня / избыточности (LRS → GRS, cool → hot) | Меняются имена счётчиков; Activity Log | Конфигурация не менялась |
| H-STO-04 | Снимки / soft delete / versioning | Счётчики объёма снимков/версий ↑ | Без изменений |

**Варианты исправления:** VACUUM / политика хранения; lifecycle-уровни; уплотнение файлов; пересмотр избыточности.
