# PB-JOBS - задачи (Jobs)

<!-- plain -->
> **Обзор.** Используйте, когда дороже стала **плановая задача**. Обычные причины: она запускается чаще, каждый запуск длится дольше, ей дали кластер побольше или она обрабатывает больше данных. Проверки их различают.
<!-- /plain -->

**Сигналы:** `5.1` SKU JOBS ↑ (классические `*JOBS_COMPUTE*` или `*JOBS_SERVERLESS*`); `5.3` объекты типа `JOB` с классом `NEW`/`GROWN`.

**Диагностика**

| # | Проверка | Источник | Что смотреть |
|---|---|---|---|
| J1 | Запусков/сутки vs стоимость/запуск по задаче, B vs C | [`6.01_job_cost_per_run.sql`](../sql/6.01_job_cost_per_run.sql) | `frequency_effect` vs `unit_cost_effect` |
| J2 | Запуски по месяцам, средняя/p95 длительность, сбои | [`6.02_job_runs_monthly.sql`](../sql/6.02_job_runs_monthly.sql) | Рост длительности, сбои ↑ |
| J3 | Старты запусков и часы работы по дням | [`6.03_job_runs_daily.sql`](../sql/6.03_job_runs_daily.sql) | День начала дополнительных запусков |
| J4 | Изменения определения (SCD2), первое появление | [`6.04_job_definition_changes.sql`](../sql/6.04_job_definition_changes.sql) | Время изменения около даты начала |
| J5 | Конфигурация кластера задачи | [`6.06_cluster_config_history.sql`](../sql/6.06_cluster_config_history.sql) (фильтр `cluster_source = 'JOB'`) | Изменение воркеров/типа узла |

**Механизмы**

| ID | Механизм | Подтверждает | Опровергает |
|---|---|---|---|
| H-JOB-01 | Новая задача по расписанию | `5.3` класс `NEW`; первое изменение в `6.04` ≈ начало; запуски стартуют ≈ начало | Задача была в B с той же стоимостью/сутки |
| H-JOB-02 | Чаще запуски (расписание/триггер, появление файла, continuous) | Эффект частоты в `6.01` ≥ 70% Δ задачи; правка расписания в `6.04` ≈ начало | Запусков/сутки не изменилось |
| H-JOB-03 | Более длинные запуски (больше данных, перекос, регрессия) | Доминирует эффект стоимости запуска; длительность ↑ при том же размере кластера; входные байты ↑ | Длительность не изменилась или её объясняет размер кластера |
| H-JOB-04 | Волна повторов / сбоев | Неуспешные запуски ↑; repair-запуски ↑; затраты на неуспешных запусках | Доля сбоев не изменилась |
| H-JOB-05 | Перенос на all-purpose кластер / более дорогой уровень (Photon, Premium) | Потребление задачи смещается с объектов `JOB` на `CLUSTER`; SKU меняется на `ALL_PURPOSE`/`PHOTON` | Тот же SKU в B и C |
| H-JOB-06 | Больший кластер задачи (воркеры, тип узла, максимум автомасштабирования) | Изменение в `6.06` ≈ начало; DBU/час на запуск ↑ | Конфигурация не менялась |
| H-JOB-07 | Миграция на serverless jobs (смена структуры) | Классические JOBS ↓ и serverless JOBS ↑ для тех же ID задач | Нет смены SKU |

**Варианты исправления:** вернуть расписание; job-кластеры вместо all-purpose; подобрать число воркеров; устранить циклы повторов (max retries, оповещения); инкрементальная обработка вместо полной перезагрузки; политики кластеров с ограничением воркеров.
